## 📌 1. Contexto e Objetivos

### Contexto

Este repositório é o resultado de um desafio prático da **DIO (Digital Innovation One)**, com foco no uso da **Inteligência Artificial como ferramenta de aprendizagem ativa**.

A proposta foi utilizar o **Google NotebookLM** como um mentor virtual de estudos, a partir da organização e análise de fontes relacionadas ao desenvolvimento de software.

Para isso, reuni materiais sobre lógica de programação, desenvolvimento web, tecnologias Full Stack e preparação para o mercado, utilizando a IA para organizar os conteúdos, identificar prioridades e construir uma trilha de aprendizagem.

O objetivo não foi aprender todas as tecnologias de uma vez, mas entender **o que estudar primeiro, o que pode ser aprofundado depois e quais conhecimentos ainda não precisam ser prioridade**.

### Objetivos de Estudo

* **Mapear a trilha Full Stack:** compreender os conhecimentos necessários para chegar a oportunidades de **estágio ou nível júnior**.
* **Consolidar fundamentos:** revisar conceitos de lógica de programação, algoritmos, variáveis, estruturas de dados e desenvolvimento web.
* **Relacionar conhecimentos:** entender como Front-end, Back-end, APIs, bancos de dados, Git e outras áreas se conectam.
* **Utilizar IA como ferramenta de aprendizagem:** experimentar o NotebookLM como apoio para pesquisa, organização e revisão dos conteúdos.
* **Praticar engenharia de prompts:** criar, testar e melhorar prompts para obter respostas mais específicas, organizadas e baseadas nas fontes disponíveis.

## 🛠️ 3. Engenharia de Prompts e "Cicatrizes" (Troubleshooting)

Durante o desenvolvimento do projeto, utilizei diferentes prompts para perceber como a forma de fazer uma pergunta influencia a resposta da IA.

A ideia foi começar com perguntas mais simples e, depois, adicionar contexto, objetivos, restrições e formatos de resposta.

### 🔹 Prompt 1 — Visão Geral de Carreira

**Pergunta:**

> "Quais são as etapas para me tornar um desenvolvedor Full Stack?"

**Resultado:**

A IA apresentou um panorama geral envolvendo etapas como lógica de programação, HTML/CSS, Git, JavaScript, frameworks, APIs, Back-end, bancos de dados, publicação de aplicações e testes.

**Análise:**

Foi útil para obter uma visão inicial da jornada, mas a resposta ainda era muito abrangente e não deixava tão claro o que deveria ser estudado primeiro.

Isso mostrou a importância de fornecer mais contexto e definir melhor o objetivo da pergunta.

---

### 🔹 Prompt 2 — Atuação como Mentor e Restrições

**Pergunta:**

> "Atue como um mentor de formação Full Stack para uma pessoa iniciante. Analise os conhecimentos necessários para chegar ao nível de estágio/júnior. Organize por 12 áreas... Para cada área indique: o que é, por que é importante, conhecimento mínimo, intermediário e o que pode ser deixado para depois."

**Resultado:**

A resposta organizou os conhecimentos por áreas e ajudou a separar aquilo que poderia ser considerado mais importante no início de assuntos que poderiam ser estudados posteriormente.

**Análise:**

Adicionar um papel para a IA, um objetivo específico e uma estrutura de resposta tornou o resultado mais organizado e útil para o estudo.

---

### 🔹 Prompt 3 — Mentor de Formação Full Stack com Fontes e Restrições

Este foi o prompt mais completo utilizado durante o projeto.

**Pergunta:**

> "Atue como um mentor de formação para uma pessoa iniciante que está se preparando para ingressar na área de desenvolvimento Full Stack, com foco em alcançar conhecimentos compatíveis com uma oportunidade de estágio ou nível júnior.
>
> Utilize prioritariamente e, sempre que possível, exclusivamente as fontes disponíveis neste notebook. Não invente informações, tecnologias, requisitos ou recomendações que não estejam sustentados pelas fontes. Quando uma informação não estiver presente nas fontes, deixe isso claro.
>
> Meu objetivo não é aprender tudo de uma vez, mas compreender o que é necessário aprender, o que é prioridade e o que pode ser estudado posteriormente.
>
> Organize a resposta nas seguintes áreas:
>
> * Fundamentos da programação
> * Lógica de programação
> * Front-end
> * Back-end
> * Bancos de dados
> * APIs
> * Git e GitHub
> * Testes
> * Segurança
> * Deploy e publicação de aplicações
> * Algoritmos e estruturas de dados
> * Soft skills
>
> Para cada área, apresente:
>
> **O que é**
> Explique o conceito de forma simples e adequada para uma pessoa iniciante.
>
> **Por que é importante**
> Explique qual é a relação desse conhecimento com a formação de um desenvolvedor Full Stack e, quando as fontes permitirem, sua relevância para estágio ou nível júnior.
>
> **Conhecimento mínimo necessário**
> Liste os conhecimentos básicos que uma pessoa iniciante deveria compreender antes de avançar.
>
> **Conhecimentos intermediários**
> Liste os conhecimentos que podem ser desenvolvidos depois que os fundamentos estiverem consolidados.
>
> **O que pode ser deixado para depois**
> Identifique assuntos mais avançados, especializados ou que não precisam ser prioridade no início.
>
> **Relação com outras áreas**
> Quando houver informação suficiente nas fontes, explique como aquela área se relaciona com as demais."

O prompt também solicitou uma tabela de prioridades e uma sequência de estudos organizada por etapas, além de reforçar que a IA deveria diferenciar fundamentos, conhecimentos intermediários e assuntos mais avançados.

**Resultado:**

A IA produziu um guia organizado da jornada Full Stack, separando diferentes áreas de conhecimento e indicando quais assuntos poderiam ser estudados primeiro ou posteriormente.

Também foram geradas uma tabela comparativa e uma trilha de aprendizagem dividida em etapas:

**Fundamentos → Desenvolvimento Web → Back-end e Dados → Integração e Qualidade → Preparação para Projetos e Mercado**

**Análise:**

Esse prompt mostrou, na prática, que respostas mais úteis podem ser obtidas quando a pergunta apresenta **contexto, objetivo, público, restrições e formato esperado**.

Também ajudou a perceber a importância de limitar a IA às fontes disponíveis quando o objetivo é estudar determinado conteúdo, evitando tratar qualquer sugestão gerada pela IA como uma informação necessariamente presente nos materiais pesquisados.

## 🪵 Cicatrizes

As "cicatrizes" representam dificuldades encontradas durante o uso da IA e o que foi aprendido a partir delas.

### 1. Desafio — Respostas muito abrangentes

Prompts muito abertos, como:

> "Me fale sobre JavaScript."

geravam respostas amplas e pouco direcionadas ao objetivo de estudo.

**Solução:**

Passei a especificar melhor o que queria aprender, o nível de conhecimento, o formato da resposta e, quando necessário, pedir exemplos práticos ou analogias.

---

### 2. Desafio — Respostas genéricas

Perguntas muito curtas nem sempre consideravam meu objetivo de chegar a conhecimentos compatíveis com estágio ou nível júnior.

**Solução:**

Adicionar contexto sobre o objetivo final ajudou a direcionar melhor as respostas.

---

### 3. Desafio — Manter as respostas relacionadas às fontes

Uma das preocupações durante o projeto foi evitar que a IA apresentasse informações como se fossem provenientes das fontes quando elas não estavam necessariamente presentes nos materiais selecionados.

**Solução:**

Passei a utilizar instruções como:

> "Utilize prioritariamente as fontes fornecidas neste notebook."

e

> "Quando uma informação não estiver presente nas fontes, deixe isso claro."

Essa experiência mostrou a importância de **não tratar uma resposta gerada por IA automaticamente como uma fonte de verdade**, mas utilizar a ferramenta como apoio ao processo de aprendizagem.

## 📖 4. Miniguia de Estudo — Entrega Final

A partir das pesquisas e das interações realizadas no NotebookLM, organizei os principais conceitos encontrados em uma visão resumida da trilha Full Stack.

### 📌 Resumo Estruturado da Trilha Full Stack

#### 1. Lógica e Fundamentos

* **Algoritmos:** sequência de passos utilizada para solucionar um problema.
* **Variáveis:** utilizadas para armazenar e trabalhar com valores durante a execução de um programa.
* **Tipos de dados:** diferentes tipos de valores utilizados por uma linguagem de programação, como textos, números e valores booleanos.
* **Estruturas de controle:** recursos utilizados para tomar decisões e repetir determinadas ações durante a execução de um programa.
* **Estruturas de dados:** formas de organizar e armazenar informações para utilização pelo programa.

#### 2. Front-end

* **HTML:** estrutura e organização do conteúdo de uma página.
* **CSS:** responsável pela apresentação e estilização das páginas.
* **JavaScript:** permite adicionar lógica e interatividade às aplicações web.
* **TypeScript:** adiciona tipagem ao JavaScript.
* **React:** biblioteca utilizada para construção de interfaces baseadas em componentes.

#### 3. Back-end e APIs

* **Node.js:** ambiente que permite executar JavaScript fora do navegador.
* **Express:** framework utilizado para facilitar a construção de aplicações e APIs com Node.js.
* **APIs:** permitem a comunicação entre diferentes aplicações ou partes de um sistema.
* **HTTP:** protocolo utilizado na comunicação entre cliente e servidor.
* **JSON:** formato amplamente utilizado para troca de dados entre aplicações.

#### 4. Banco de Dados

* **SQL:** linguagem utilizada para trabalhar com bancos de dados relacionais.
* **MySQL / PostgreSQL:** exemplos de sistemas de gerenciamento de bancos de dados relacionais.
* **NoSQL:** categoria de bancos de dados que utiliza outros modelos de organização além do modelo relacional.
* **MongoDB:** exemplo de banco de dados orientado a documentos.
* **CRUD:** operações básicas de criação, leitura, atualização e exclusão de dados.

#### 5. Git e GitHub

* **Git:** sistema de controle de versão utilizado para acompanhar alterações no código.
* **GitHub:** plataforma utilizada para hospedar e compartilhar repositórios Git.
* **Commit:** registro de alterações realizadas no projeto.
* **Branch:** ramificação utilizada para trabalhar de forma independente em alterações.
* **Pull Request:** recurso utilizado para propor e revisar alterações antes de integrá-las a outra branch.

---

## 📑 Glossário de Conceitos Fundamentais

* **Full Stack:** área de desenvolvimento que envolve conhecimentos de Front-end e Back-end, incluindo a comunicação com serviços e bancos de dados.
* **DOM (Document Object Model):** representação estruturada dos elementos de uma página HTML que pode ser manipulada pelo JavaScript.
* **Array:** estrutura utilizada para armazenar uma coleção de valores.
* **CRUD:** conjunto das operações básicas de um sistema de dados: Create, Read, Update e Delete.
* **API:** mecanismo que permite a comunicação entre diferentes sistemas ou componentes.
* **API REST:** abordagem para construção de serviços que utiliza recursos e métodos do protocolo HTTP.
* **Git:** sistema distribuído de controle de versão.
* **GitHub:** plataforma para hospedagem e colaboração em projetos utilizando Git.
* **Deploy:** processo de disponibilizar uma aplicação em um ambiente onde ela possa ser executada e acessada.

## 🔁 5. Prompts Reutilizáveis para Estudos Futuros

Os prompts abaixo podem ser reutilizados no NotebookLM em futuras sessões de estudo.

### 1. Criador de Analogias Didáticas

```text
Explique o conceito de [CONCEITO TÉCNICO] utilizando uma analogia simples do mundo real.

Depois da analogia, explique o conceito tecnicamente de forma adequada para alguém que está aprendendo.

Utilize prioritariamente as fontes disponíveis neste notebook.
```

### 2. Explicador de Erros

```text
Estou recebendo o seguinte erro:

[COLE O ERRO]

Meu código utiliza:

[TECNOLOGIA]

Com base nas fontes disponíveis neste notebook:

1. Explique o que esse erro significa.
2. Explique a possível causa de forma simples.
3. Mostre quais pontos do código devo verificar.
4. Apresente um passo a passo para tentar resolver o problema.

Não invente informações que não estejam sustentadas pelas fontes.
```

### 3. Gerador de Desafios Práticos

```text
Com base nos conteúdos de [TEMA], crie 3 pequenos exercícios práticos de fixação para o nível iniciante.

Não apresente as respostas imediatamente.

Aguarde minhas tentativas e, depois, avalie cada resposta indicando:
- o que está correto;
- o que precisa ser melhorado;
- como eu poderia pensar para chegar à solução.

Utilize prioritariamente os conteúdos disponíveis neste notebook.
```

### 4. Simulação de Entrevista Técnica

```text
Atue como um entrevistador técnico para uma vaga de Desenvolvedor Full Stack em nível de estágio/júnior.

Faça uma pergunta conceitual sobre [TECNOLOGIA/TEMA] por vez.

Aguarde minha resposta antes de enviar a próxima pergunta.

Depois que eu responder:
1. Avalie minha resposta.
2. Indique os pontos que estão corretos.
3. Explique o que pode ser melhorado.
4. Dê uma explicação curta sobre o conceito.
5. Somente depois faça a próxima pergunta.

Faça um total de 3 perguntas.

Pode começar com a primeira pergunta.
```

## 🎯 Conclusão

A principal aprendizagem deste desafio não foi apenas sobre desenvolvimento Full Stack, mas também sobre **como utilizar a Inteligência Artificial de maneira mais consciente durante o processo de aprendizagem**.

Ao longo do projeto, percebi que a qualidade da resposta depende bastante da forma como o problema é apresentado. Quanto mais claro o objetivo, o contexto, as restrições e o resultado esperado, mais útil tende a ser a interação.

O NotebookLM foi utilizado como um **mentor virtual de estudos**, ajudando na organização das informações e na construção de uma trilha de aprendizagem baseada nas fontes pesquisadas.

O resultado deste projeto é, portanto, um **mapa de estudos**, e não uma afirmação de domínio das tecnologias apresentadas.

A intenção é utilizar esse material como ponto de partida para continuar estudando, praticando e desenvolvendo projetos ao longo da minha formação em Engenharia de Software.
